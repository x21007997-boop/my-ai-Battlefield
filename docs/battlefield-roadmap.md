# 历史战争认知沙盘：持续研发计划

> 这是正式游戏研发执行清单，不是汇报材料。每次自动推进只处理当前阶段中最靠前的一个未完成任务；完成后必须通过对应验收，再进入下一阶段。

## 执行规则

- 正式目标是 Godot 历史战争实时推演游戏；React 仅用于迁移期验证和数据编辑。
- 战场规则、历史剧本、指挥官认知投影和回放数据独立于 Godot；Godot 不成为规则真值来源。
- 地图是结构化矢量沙盘，敌情只通过延迟、带置信度和可能偏差的情报进入玩家视野。
- 每次命令必须有即时反馈，并能在后续时间推进中看到可理解的结果。
- 不把历史事实、历史估计、剧本假设和模拟变量混写；修改战役资料后运行剧本校验。
- 每个阶段完成后运行相关测试；涉及正式链路的阶段必须运行完整质量门禁，并提交到 `origin/main`。
- 遇到需要历史取舍、外部账号权限、破坏性操作或产品决策时暂停并通知，不自行猜测。

### 2. 历史时间、距离与行军规则基础

- [ ] 新增版本化 `scenario calendar` 契约：战役起始历史日期、日内时刻、时辰/刻换算、日出日落及可选历法说明。
- [ ] 内核继续使用单调连续时间保证确定性，所有玩家界面、军报和回放统一通过时间格式化层显示历史日期与时辰，不直接显示秒数。
- [ ] 为每条道路补齐距离、道路类型、坡度/河流/关隘、通行能力、隐蔽性、辎重限制和资料状态；`travelSeconds` 降级为兼容字段而非剧本真值。
- [ ] 建立移动耗时模型：距离 × 兵种速度 × 地形 × 天候 × 昼夜 × 疲劳 × 辎重 × 道路拥堵，并区分传令骑兵、斥候和成建制部队。
- [ ] 所有预计时间只投影玩家已知信息，显示“约四十里”“次日辰时前后”等区间，不泄露精确真值。
- [ ] 完成旧长平路线数据迁移、Schema 校验、确定性测试和回放兼容测试。

验收：同一路段由传令骑兵、轻装部队和携带辎重的大军通过时耗时不同；跨日行军、昼夜与日落可正确显示；历史时间和回放结果稳定一致。

### 3. 结构化路网与连续行军

- [ ] 将道路、山路、河谷、渡口、桥梁、关隘和临时路线建成可计算的结构化路网，沙盘与内核共用同一份几何和属性数据。
- [ ] 部队沿路线分段推进，记录离营、进入路段、渡河、翻山、通过关隘、受阻、改道、抵达和扎营，不再只在区域间跳转。
- [ ] 增加路线规划与比较：预计里程、耗时区间、补给压力、暴露风险和依据新鲜度；允许副将根据判断改道。
- [ ] 区分计划路线、己方确认路线、失联后推测路线、敌军疑似路线和回放轨迹，使用不同线型与可信度表现。
- [ ] 增加地图比例尺、指北、测距和路线预览，但测量精度受舆图与情报质量约束。

验收：军队移动位置由路网进度决定；过河与翻山由真实经过的结构化地形触发；敌方真实路线不进入玩家沙盘。

### 4. 指挥链与自由军令深化

- [ ] 将“将军—副将—传令兵—部队”的当前状态在玩家界面中做成可理解的指挥关系。
- [ ] 显示副将在场/离场、命令传递路径、按历史时间表达的预计抵达，以及副将接受/修改/拒绝命令的原因。
- [ ] 扩充自由军令解析，但所有解析结果必须落到可审计的结构化命令，不允许直接改写世界状态。
- [ ] 支持从自然语言提取接令人、部队、目标、出发时机、截止时刻、路线偏好、行军姿态和约束，并在盖印发令前让玩家确认解释结果。
- [ ] 增加副将基于 readiness、地形风险、补给、预计时限和敌情可信度的可解释决策差异。

验收：同一条命令交给不同位置和状态的副将，能产生不同且可解释的传令、等待、改道或拒绝结果；不泄露敌军真值。

### 6. 新玩家引导与真实试玩验收

- [ ] 玩家进入后立即看懂“我是谁、当前危机、我能命令谁、为什么不能看到真实敌军”。
- [ ] 30 秒内理解“选副将/部队—规划目标与路线—下令—等待传令—看军报—继续推进”。
- [ ] 60 秒内完成第一道自由军令，不依赖阅读开发日志或规则说明。
- [ ] 不看详细日志也能判断命令是在传递、整备、执行、受阻、完成还是失效。
- [ ] 对首次试玩记录理解错误、误点击和放弃点，并只修影响核心循环的问题。

验收：至少一名未接触代码的试玩者可独立完成机动和侦察，并能正确解释敌军标记是可能失真的情报。
