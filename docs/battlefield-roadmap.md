# 历史战争认知沙盘：持续研发计划

> 这是正式游戏研发执行清单，不是汇报材料。每次自动推进只处理当前阶段中最靠前的一个未完成任务；完成后必须通过对应验收，再进入下一阶段。

## 执行规则

- 正式目标是 Godot 历史战争实时推演游戏；React 仅用于迁移期验证和数据编辑。
- 战场规则、历史剧本、指挥官认知投影和回放数据独立于 Godot；Godot 不成为规则真值来源。
- 地图是结构化矢量沙盘，敌情只通过延迟、带置信度和可能偏差的情报进入玩家视野。
- 每次命令必须有即时反馈，并能在后续时间推进中看到可理解的结果。
- 不把历史事实、历史估计、剧本假设和模拟变量混写；修改战役资料后运行剧本校验。
- 每个阶段完成后运行相关测试；涉及正式链路的阶段必须运行完整质量门禁，并提交到 `origin/main`。
- 遇到需要历史取舍、外部账号权限、破坏性操作或产品决策时暂停并通知，不自行猜测。

## 阶段清单

- [x] Godot 16:9 保持比例、最小分辨率和基础 HUD 状态反馈。

### 1. 当前优先：真实试玩可读性验收

- [ ] 在 1280×720、960×540 和一台宽屏窗口下完成 Godot 实机试玩记录。
- [ ] 修复影响理解的布局问题：左侧地图工具、右侧指挥栏、顶部状态和底部反馈不得重叠、裁切或变形。
- [ ] 确认第一次进入时玩家能在 30 秒内理解“选部队—选区域—下令—等待传令—看情报—继续推进”。
- [ ] 确认机动中的旗帜、渡河/翻山状态、报告置信度和报告失效在地图上可辨识。
- [ ] 为每个拒绝、传递、执行、完成、过期和恢复状态补充可见反馈，并用 Godot smoke test 固化。

验收：新玩家不看代码即可完成一条机动命令和一次侦查；三种窗口比例下无严重裁切；相关测试通过。

### 2. 指挥链与自由度深化

- [ ] 将“将军—副将—传令兵—部队”的当前状态在玩家界面中做成可理解的指挥关系。
- [ ] 显示副将在场/离场、命令传递路径、预计抵达和副将接受/修改/拒绝命令的原因。
- [ ] 扩充自由军令解析，但所有解析结果必须落到可审计的结构化命令，不允许直接改写世界状态。
- [ ] 增加副将基于 readiness、地形风险、补给和敌情可信度的可解释决策差异。

验收：同一条命令交给不同位置和状态的副将，能产生不同且可解释的传令、等待、改道或拒绝结果；不泄露敌军真值。

### 3. 战场反馈与战术表现

- [ ] 将命令状态、行军进度、地形穿越、后勤压力和前线报告统一成时间线与地图状态。
- [ ] 增加必要的沙盘视觉层：秦军旗、疑似赵军旗、城市、粮仓、堡垒、关隘、渡口和山口。
- [ ] 不显示原始战斗交换；将接触、交战和战果转换为延迟前线报告。
- [ ] 补充轻量动画：传令移动、行军标记、报告脉冲、情报失效和战局阶段变化。

验收：玩家能从地图和报告判断“我下达的命令产生了什么后果”，但无法直接看到未侦知的敌军位置或战斗真值。

### 4. 长平关卡打磨

- [ ] 用已确认或明确标注的历史资料复核初始兵力、地形、补给、侦查和时间窗口。
- [ ] 调整敌方 AI 节奏，使等待、误判、反侦察和反制形成可玩的连续压力。
- [ ] 为至少三种指挥思路提供可行但代价不同的结果：正面推进、切断粮道、诱导误判。
- [ ] 固化关键胜负路径和失败路径的回放测试，避免“抵达即胜”。

验收：长平战役可以独立完成一局，玩家策略而非固定按钮顺序决定结果；场景校验和回放测试通过。

### 5. 正式客户端完善

- [ ] 完善新局、恢复、回放、退出和异常重连的状态边界。
- [ ] 增加存档损坏、内核不可用和版本不兼容时的用户可理解提示。
- [ ] 完成 Godot 导出包、桌面运行配置和基础发行验证。
- [ ] 对常用分辨率进行一次视觉回归，必要时建立截图基线。

验收：普通用户可以启动、开局、暂停、恢复、另开一局、导出回放并重新载入，不需要手工清理文件。

### 6. 扩展内容与联机预留

- [ ] 在长平闭环稳定后，再选择第二个真实历史战役作为独立剧本包。

- [ ] 只有在明确需要多人或云端持续推演时，才评估 WebSocket、账号和云存档。

验收：第二战役不修改通用规则核心；联机能力不破坏单机实时体验和信息边界。
