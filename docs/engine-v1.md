# 推演内核 V1

## 目标

第一版内核负责打通“阅读奏报 → 下达决策 → 影响预演 → 规则结算 → 事件触发 → 自动存档”的最小闭环。规则引擎是正式状态的唯一来源，界面和未来 AI 只能提交决策或读取结果。

## 世界状态

世界快照由以下部分组成：

- `scenarioId`：剧本标识；
- `ruleVersion`：规则版本；
- `turn`、`seed`：当前回合与可复现随机种子；
- `metrics`：国库、粮草、民心和有效防务；
- `cities`：城市控制权、粮食、驻军和动荡；
- `officials`：官职、位置、忠诚和能力；
- `pendingEffects`：尚未到期的延迟影响；
- `flags`：剧本条件标记；
- `history`：完整决策与结算记录。

## 支持的决策

| 行动 | 识别示例 | 主要影响 |
| --- | --- | --- |
| 调运粮草 | “调拨二十万石粮草赈济淮安” | 消耗国库和粮草，提高民心，降低当地动荡 |
| 调动军队 | “调动五万兵力增援扬州” | 消耗军饷和粮草，提高当地驻军与有效防务 |
| 派遣官员 | “派遣史可法前往淮安查办” | 产生行政成本，更新官员状态并形成延迟成效 |

未被 V1 规则覆盖的指令会被明确拒绝，不会用假数据推进回合。

## 结算顺序

1. 解析玩家原始命令；
2. 验证行动类型、目标和数量；
3. 生成即时影响与风险提示；
4. 玩家确认后应用当前回合影响；
5. 结算上一回合到期的延迟效果；
6. 更新城市或人物状态；
7. 使用固定种子触发事件；
8. 记录原始命令、结构化行动、规则版本、种子和结果；
9. 写入浏览器自动存档。

## 复现约束

相同的世界快照、规则版本、原始决策和随机种子必须得到相同结果。自动化测试覆盖三类决策解析、非法决策拒绝、确定性复现以及连续三个回合的延迟效果结算。

## V1 边界

- 目前是关键词和规则模板解析，不是大模型语义解析；
- 快照仅保存在浏览器本地；
- 事件库仍为最小示例；
- 尚未实现读取旧存档、分支树和历史回放动画；
- 人物关系、派系和不完全信息尚未进入正式计算。

## 三个月剧本

V1.1 在规则内核上增加了第一段可玩内容：

1. 九月：淮安粮荒。优先调粮可以恢复粥厂，忽视粮荒则会触发饥民冲仓；
2. 十月：扬州江防。补充兵力或提前提高防务可完成换哨，否则可能发生营兵逃散；
3. 十一月：南京廷议。系统根据国库、民心和防务形成 `江北暂安`、`强兵弱政` 或 `江北离心`。

每个剧本事件都包含触发回合、条件、指标影响、世界标记、奏报文本和后续叙事。界面中的月度奏报来自实际结算事件，而非固定轮播内容。
