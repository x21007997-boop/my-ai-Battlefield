# 历史战争认知沙盘：Godot 游戏客户端

这是正式游戏客户端的第一版垂直切片，不是独立的历史数据副本。

## 数据来源

长平客户端数据由仓库根目录下的 `scenarios/changping-260/` 生成：

```text
npm run godot:sync
```

生成结果位于 `godot/data/changping-260.json`。正式客户端使用 `vector-terrain` 沙盘：河流、山脊、渡口和山口均来自场景结构化数据，不依赖地图贴图。
其中 `commanderSession` 由通用战场内核生成，Godot 只接收指挥官可见投影和安全事件流。每条机动路线还携带地形穿越段，供内核判定和客户端反馈共同使用。

Godot 默认尝试连接本机的实时内核网关 `http://127.0.0.1:4317`。连接成功后，命令和时间推进由通用内核处理，Godot 只消费返回的会话快照与事件增量；如果网关没有启动，则自动回退到本地垂直切片。

从仓库根目录运行 `npm run playtest`，会自动启动本地战场内核并打开 Godot 游戏客户端。也可以设置 `BATTLE_ENGINE_URL` 连接其他兼容网关。

## 当前垂直切片

- 历史背景沙盘；
- 结构化河流、山脊与区域地形；
- 仅在下达军令后显示的动态机动意图线；
- 我方旗帜；
- 延迟前线报告旗；
- 前线情报详情面板：来源、可信度、误差提示、回传倒计时和有效剩余时间；
- 统帅层战局面板：战役意图、时间压力、资源压力和信息边界；
- 命令传递与执行延迟；
- 移动与坚守两类正式命令；
- 连续时间推进；
- 报告有效期和失效；
- 多计策选择面板：每项计策显示准备时间、资源消耗和投放目标，由玩家明确选择；
- 部队进入/离开渡河段、山脊段的实时事件；
- 点击我方旗帜选中部队、点击区域选择目标；
- 鼠标滚轮缩放、中键拖拽和视野复位；
- 可将本局指挥事件导出为 `user://changping-replay.json`；
- 可载入上一局回放，按时间轴播放、暂停和跳转，并从事件流重建指挥官视图；
- 回放可以重建 `battle_ended` 结果，但战役胜负规则由通用战场内核和场景包提供；
- 任务目标、时间上限、胜负结果和战后复盘摘要由通用战场内核下发；
- Godot 场景不接收敌军真实单位或战斗交换数据。

当前环境如果尚未安装 Godot，仍可先执行数据同步和 JavaScript 侧测试。Godot 工具链安装完成后，使用 Godot 4 打开本目录中的 `project.godot`。
